# 新 API の基盤構築（旧システムからのリニューアル）

## プロジェクト全体での担当規模

旧システムを NestJS + TypeORM で作り直すリニューアルプロジェクトに参画しました。

| 集計範囲 | PR 数 | 追加 | 削除 | 合計 |
| --- | --- | --- | --- | --- |
| マージ済みの機能 PR | 125 | +22,858 | −6,677 | 29,535 |

- 自動生成の lock ファイル（`yarn.lock` / `package-lock.json`）は集計に含めていません
- 既存コードを本番系ブランチへ反映するだけのリリース PR も、新規開発ではないため除いています
- まとめると **約 125 PR、追加約 2.3 万行・削除約 6,700 行、合計約 3 万行**

以下では、そのうちプロジェクトの土台を作った最初の PR について説明します。

## 概要

| 項目 | 内容 |
| --- | --- |
| 時期 | 2021年3月（約1ヶ月、18コミット） |
| 規模 | 181ファイル、+1,539 / −1,804 行（lock ファイル除く） |

この PR の中心は業務 API そのものではなく、**プロジェクト基盤の再構築**です。その後に開発した各業務 API（20本以上の PR）は、すべてこの土台の上に作られています。

## 1. ディレクトリ構成の整理

- 機能単位のモジュール（ユーザー、ロール、フォロー、ニュース、お問い合わせ、タグ等）を `src/models/*` から `src/modules/*` へ移動（72ファイル。コードはほぼ変更なし）
- 旧ディレクトリ配下のベースクラス・Entity・試作コードを削除

## 2. 共通ベースクラス（`src/common/bases/`）

| ファイル | 役割 |
| --- | --- |
| `base.model.ts` | Entity のベースクラス。TypeORM の `BaseEntity` を継承し、`createdAt` / `updatedAt` を共通管理 |
| `base.service.ts` | Service の抽象ベースクラス。一覧・単体取得・削除・論理削除などの共通処理と例外処理を集約 |
| `base.repository.ts` | ジェネリクスの Repository ベースクラス。`paginate()` / `searchPaginate()` を内蔵し、各モジュールでそのまま再利用可能 |

## 3. 共通ページネーション（`src/common/pagination/`）

- 1始まりのページ番号、1ページ上限 100 件
- `include` パラメータで関連データを読み込み、取得カラムの指定にも対応
- `sort` / `direction` による並び替え。不正な並び順は自動で `ASC` にフォールバック
- `findAndCount` で一覧と総件数を1回で取得
- 検索条件のベースクラス、ページ情報の生成処理も用意
- **旧システムのロジックを踏襲し、API 仕様（クライアントから見た挙動）を変えない**ことを重視

## 4. 検索条件クラス

主要リソースの検索条件として、カテゴリ・ユーザー・特定 ID の除外・お気に入り有無・公開ステータス・ランダム並びなどの絞り込みを実装。デフォルトで有効期限内のデータのみを対象にし、関連データも合わせて読み込みます。

## 5. データモデル（`src/entities/`）

- 新規 Entity 7つ（主要リソースとそのタグ・お気に入り・インスタンス、チャット関連）
- 既存 Entity のリファクタリング
  - カラム名をスネークケースからキャメルケースに統一
  - 外部キーの命名を整理
- NestJS と組み合わせるとエラーになる `typeorm-plus` を外して標準の TypeORM に統一し、一部の生 SQL も書き直し

## 6. マイグレーションとテストデータ（`src/database/`）

- **Migration**：テーブルごとに分かれていた旧 Migration 12本を削除し、全テーブルを作成する初期 Migration 1本に集約
- **Seed**：番号順に実行される Seed 15本に再構成
- **Factory**：テストデータ生成用 Factory を 9本新規追加・5本変更し、旧来の汎用 Factory を廃止

## 7. 共通ユーティリティと Enum

- ID 体系の定義（種別ごとに桁数を固定）
- `nanoid` + 見間違えにくい文字セット（`0/O`、`1/l` などを除外）による一意 ID 生成
- Enum 値の表記を大文字に統一
- 更新成功時の共通レスポンスヘルパーを追加
- ロールガードの調整（仕様未確定のため、ガードの仕組みだけ先に用意）

## 8. 開発環境の整備

- ESLint、Jest、TypeORM（接続・Migration・Seed）、VS Code デバッグ設定を追加
- 開発用 Dockerfile、`.env.example`、`package.json`、`tsconfig.json`、ルートモジュールを更新
- 認証モジュール（Controller / Service / JWT Strategy / テスト）も合わせて調整

## まとめ

- リニューアル後の API の**土台**として、共通ベースクラス・ページネーション・データモデル・マイグレーション/テストデータ・開発環境を一通り整備
- 各機能が共通の Service / Repository / ページネーションを再利用できる構成にしたことで、以降の業務 API 開発を効率化
- 旧システムと API 仕様の互換性を保ちつつ、内部構造を作り直した
